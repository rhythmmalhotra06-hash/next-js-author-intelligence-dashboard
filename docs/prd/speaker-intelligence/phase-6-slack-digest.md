# Phase 6 — Weekly Slack Intelligence Digest

> Part of [Mindvalley Speaker Intelligence System](../speaker-intelligence.md)

## Purpose

The dashboard (Phase 5) is a pull surface — users must remember to open it. The digest is a push surface — intelligence surfaces where Marijana and Marta already are, without requiring a new habit.

The material of this system is async data refreshed weekly and AI-generated qualitative analysis. That material naturally produces a narrative, not a UI someone navigates. A weekly Slack message — written by Claude, grounded in the latest data — closes the loop between the analytical engine and the planning decisions it is meant to inform.

This phase answers: how do we make sure the signal reaches the decision-maker every week, not just when they remember to check the dashboard?

## User Stories

As a curriculum planner: I want a short Slack message each week that tells me what's new, what's flagged, and who stood out — so I don't have to open the dashboard to stay current.

As an author relations lead: I want a digest that surfaces divergence flags and trajectory changes automatically — so a declining author doesn't slip through between planning cycles.

As a financial accountability stakeholder: I want to be pinged when a high-cost author's craft signals drop or when a high-value, low-cost author is identified — not when I happen to check a dashboard.

## Workflows

**Weekly Digest Generation**
1. Trigger on weekly Airtable MCP refresh completing (same cadence as dashboard refresh)
2. Pull delta since last digest: new session data, rating changes, rewatch movements, feedback batches processed
3. Pass current author signal state through Claude API with structured prompt
4. Claude generates narrative digest in plain English — not a data dump, a briefing
5. Post to designated Slack channel (e.g. `#speaker-intelligence`) via Slack MCP

**Digest Structure (target: readable in 90 seconds)**
- **Headline**: one sentence — what is the most important signal this week?
- **Flags** (up to 3): authors or curriculum slots with new divergence signals, trajectory drops, or follow-up rate spikes
- **Standout** (1): highest-performing author or session this week with the signal that earns it
- **On the radar**: 1–2 items that don't need action yet but are worth watching
- **Link**: deep-link to the relevant author profile or drill-down view in the dashboard

**Example output format**
> **Speaker Intelligence — Week of 5 May 2026**
>
> This week's signal: rewatch rates across Speaking & Influence dropped 18% cohort-over-cohort while live attendance held steady — a potential engagement cliff worth investigating.
>
> **Flags**
> - Vishen Lakhiani (Speaking): craft score strong (4.7 avg), but transformation language rate fell to 12% this cohort vs 34% last — curriculum fit divergence. [View profile →]
> - Module 3 (Manifesting): third consecutive cohort below 4.0 avg rating regardless of speaker — slot-level pattern, not author problem. [View drill-down →]
> - Lisa Nichols (AI Mastery): follow-up rate at 22%, up from 9% last cohort. [View profile →]
>
> **Standout**
> - Srikumar Rao (Entrepreneurship): highest rewatch long-tail this cohort (1.8×), indicating reference value beyond the live session. Cost-per-session remains in bottom quartile. [View profile →]
>
> **On the radar**
> - Two speakers with ≥3 masteries showing rating consistency below 0.4 std deviation — worth flagging as anchor candidates at next planning cycle.

**Recipient model**
- Post to a shared Slack channel (not DM) so the whole team sees the same signal
- No personalisation by recipient in v1 — one digest, one channel
- Recipients can react or thread-reply to flag items for follow-up; no automated reply handling in v1

## Boundaries

- Digest is generated by Claude (`claude-sonnet-4-6`) using structured data from Phases 1–4 as context
- Plain English narrative only — no tables, no raw numbers dumped into Slack
- Digest links to the dashboard (Phase 5) for full detail; it does not replicate the dashboard in Slack
- No interactive Slack commands or bot replies in v1 — publish-only
- Frequency: weekly, aligned to Airtable MCP refresh cadence; no on-demand generation in v1
- Slack channel and recipient list confirmed before build — not hardcoded

## Dependencies

- Phases 1–3 complete (craft signals, cross-mastery join, finance overlay) as minimum viable dataset for digest
- Phase 4 AI analysis additive — digest is richer with qualitative signals but not blocked by them
- Phase 5 dashboard links must be resolvable (digest deep-links to author profiles and drill-down views)
- Slack MCP access configured and tested
- Claude API access (`claude-sonnet-4-6`) for digest generation
- Slack channel name and recipient list confirmed by Marijana before first send

## Success Criteria

- Digest posts to Slack every week without manual trigger
- Digest is read by Marijana or Marta within 24 hours of posting (measured by Slack read receipts or thread replies)
- At least one digest flag leads to a dashboard drill-down visit within the same week
- Zero false positives in first month: every flag surfaced is confirmed as a real signal (not noise) by Marijana
- Marijana rates digest as "useful" in first retrospective after two cycles of use
